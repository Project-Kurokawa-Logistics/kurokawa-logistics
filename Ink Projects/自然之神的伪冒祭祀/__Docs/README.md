# 《自然之神的伪冒祭祀》文档区

这里存放本 Ink 项目的设计记录、流程索引、变量索引、编写约定、重构规范、Kimi Code 交接与待确认问题。**本目录中的 Markdown 是辅助文档，不会被主 Ink 文件自动载入。**

## 文档索引

- [重构规范](REFACTORING_SPEC.md)：目标架构、目录原则、状态管理、系统边界、迁移流程和验收标准。
- [Kimi Code 重构交接](HANDOFF.md)：第一阶段盘点与实测结果、实施边界、迁移顺序、首批任务和交付标准。
- [故事流程与分支总览](STORY_FLOW.md)：按当前源码记录入口、主要章节、分支和结局。
- [Ink 编写约定](INK_CONVENTIONS.md)：区分项目中已经使用的写法与建议采用的维护规范。
- [变量与状态索引](VARIABLES.md)：记录已确认的核心变量、命名习惯和状态重置注意事项。
- [待确认问题与 TODO 清单](OPEN_ISSUES.md)：集中登记未完成选项、可疑跳转、角色连续性和需要试玩确认的逻辑。

## 记录原则

为避免把推测写成设定，文档使用以下标记：

- **源码事实**：可以在当前 .ink 文件中直接找到依据。
- **已确认设计**：作者明确说明的设计意图。
- **待验证/待确认**：静态阅读发现的疑点，或作者尚未决定的设计。
- **建议**：推荐的后续维护方式，不代表现有源码已经遵循。
- **未完成**：源码明确含有 TODO、禁用标记或占位流程。

## 文档对应的源码范围

主要入口是 [自然之神的伪冒祭祀.ink](../自然之神的伪冒祭祀.ink)。当前入口通过 INCLUDE 汇总 `Characters/`、`Functions/`、`Maps/`、`Menus/`、`Misc/` 和 `Pages/` 中的脚本。目标架构允许逐步按大场景整理目录，但不能把目标目录误认为当前源码结构。

## 维护规则

1. 新增、删除或重排重要剧情节点后，更新 `STORY_FLOW.md`。
2. 新增或改变状态变量、结局标记后，更新 `VARIABLES.md`。
3. 发现尚未实现的选项、可疑跳转或角色关系问题时，更新 `OPEN_ISSUES.md`；确认修复后记录解决方式。
4. `INK_CONVENTIONS.md` 中的“现有写法”应以源码为准；“建议”应明确标注。
5. 架构、目录、迁移策略变化时更新 `REFACTORING_SPEC.md`。
6. 在 Kimi Code 中进行重构时遵循 `HANDOFF.md` 的实施、验证和交付流程。
7. 修改分支后，检查入口、选项目标、返回路径和终止路径；若运行环境可用，应编译 Ink 并实际走通相关路线。

## 当前工作约定

第一阶段只读盘点已完成。后续重构在 Kimi Code 中推进，编码默认由 `deepseek-flash` 子代理实施，Kimi Code 负责审阅与自验，作者对未定的剧情规则和行为变更作最终决定。每批工作先确认最新 `main` 和授权范围，再在独立工作分支中小步实施；不得把历史审查 SHA 当成最新基线，也不得未经批准直接全面重写。
