## 维护约定

- **运行时源码是事实来源。** 图与表描述当前文件，不代表作者最终设定；改剧情跳转、解锁条件、结局计数时，同次提交应更新文档。
- **图的存放方式：** Mermaid 源码直接嵌入 Markdown，GitHub 可渲染；Obsidian 若启用 Mermaid 支持也可浏览。不要同时维护一份易过期的图片副本。
- **图的粒度：** 主图负责“从哪到哪”，事件表负责“条件及副作用”，不把每句对白画成节点。复杂场景可另加局部子图。
- **审核口径：** 先读文档并确认规范，再单独修改 Ink；重命名变量时必须一起修改所有读写处。
- **验证边界：** 本次为源码静态检查，未执行 Inky／Ink 编译和所有多周目路径测试。

## 为什么不立刻改名？

既有 Knot／Stitch 名称和全局变量参与跨文件跳转及条件判断。一次性重命名容易改变可达性；本阶段先把“现状”和“推荐写法”分开记录，等具体剧情改动需要时再渐进迁移。
