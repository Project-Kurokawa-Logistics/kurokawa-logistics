## 2. 已经写入源码的修改

### `Z_VAR.ink`

- 新增 `Ending_F1_Achieved` 至 `Ending_F11_Achieved` 共 11 个布尔变量，用于表示正片实际达成过的结局。
- 新增 `IsPreviewMode`，区分正片流程与从结局回顾/开发者菜单直接预览。
- `CountFinale` 改为统计结局达成标记，而不是统计 Knot 访问历史。
- `FinaleList` 只显示已达成的结局；从回顾入口重看时设置预览状态。
- `All_Finale` 的全部结局预览入口设置预览状态。
- `CleanData` 会重置当前周目的好感度、角色选择计数与预览状态，但不会清除正式结局达成标记。这是为了让普通新周目保留结局回顾进度。

### `Z_Finale.ink`

- F1–F11 各结局在结束前都有 `not IsPreviewMode` 保护，只有正片流程才会设置相应达成标记。
- F8 同时承载公共剧情和分流。当前实现仅在选择“担心身体”并走完该分支时记录 F8；进入 F9/F10 不应记录 F8。
- F9 的入口条件改为正式达成 F2；F10 的入口条件改为正式达成 F2 与 F7。
- F8 正文分类标题已从“好结局”同步为“一般结局”。

### `Z_End.ink`

- 在 `TheEnd` 入口重置 `IsPreviewMode`，避免预览状态泄漏到后续流程。

**注意：以上是源码变更清单，不是测试通过声明。** 这些修改仍需由 DeepSeek 审查 Ink 语法、状态生命周期与实际运行结果。尤其要检查所有入口和回顾/预览跳转是否覆盖完整，以及宿主的 RESTART 行为是否符合设计。

## 3. 作者确认的设计意图：不可擅自“修复”

以下内容是作者明确确认的需求，必须视为验收条件：

| 编号 | 作者确认 | 实现要求 |
|---|---|---|
| A-01 | 宿舍线的意思是“只要选择过他们中的谁”即可，不是最高计数竞争 | 不要用最高倾向值决定路线。改为明确的“是否选择过”条件；多个角色都被选择时的优先级仍需明确，不可悄悄发明新规则 |
| A-02 | F8 统计有问题，作者要求修复 | F8 是公共剧情/分流节点；只有选择“担心身体”并走完该结局才记录 F8 |
| A-03 | F5 的重复“服从”选项是故意设计，用来表现主角已经沦陷 | 三个重复选项全部保留，不合并、不改写 |
| A-04 | 黑蜘蛛快餐店确实由雷琥哥哥经营 | 这是既定设定，不要当成剧情矛盾自行改文 |
| A-05 | 结局分类以结局回顾菜单为准 | F8 分类应为“一般结局《担心身体》” |
| A-06 | F6 的不同选项汇合到相同后果是有意的表现形式 | 保留选项与汇合结构，不强行改成不同后果 |
| A-07 | 结局回顾只展示在正片游戏中实实在在达成过的结局 | 仅访问 Knot、从开发者菜单预览或使用“查看所有结局”都不能自动登记正式达成 |

此外，作者提到游戏已有通过连续点击解锁的开发者菜单，可直接查看所有结局。当前源码中的 `Dev_Unlock` 与 `All_Finale` 机制应保留，不要删除或改成需要正常通关才能使用。

### 第二步：完成 A-01 宿舍线判定

当前 `G_Dormitory.ink` 仍使用类似以下条件：

- `Choose_YeHen > (Choose_CenYe or Choose_LeiHu)`
- `Choose_CenYe > (Choose_YeHen or Choose_LeiHu)`
- `Choose_LeiHu > (Choose_YeHen or Choose_CenYe)`

作者已经明确：语义不是比较最高计数，而是“选择过对应角色即可作为路线资格”。请把这一逻辑改写为清楚、符合 Ink 类型规则的条件，例如检查相应计数是否大于 0。

**尚待明确的边界：** 如果夜痕、岑烨、雷琥有两个或三个角色都被选择过，究竟采用什么优先级？最小改动的候选方案是沿用当前代码的顺序（夜痕 → 岑烨 → 雷琥），但这只是建议，不是作者已明确确认的规则。请在 Work 任务中先把多角色冲突情况和候选方案说明给作者；若无法从现有剧情或测试明确推出规则，不要悄悄把建议当成已确认需求。

保持 `Rate_LeiHu < 3` 与 `Rate_LeiHu >= 3` 的分界，不要改变其他好感度逻辑。三个角色选择计数全为 0 时，当前默认 F7 的行为应继续保留，除非作者另行决定。

### 第三步：审查并完善 A-02 / A-07

请审查已提交的结局达成逻辑，确认：

- 每个结局只在正片走完时登记，预览不登记。
- F8 的公共剧情不登记 F8；只有“担心身体”分支登记 F8。
- F9/F10 的解锁依据是正片正式达成标记，而不是 Knot 被访问或开发者预览。

- 重复达成同一结局不会重复计数。
- 普通“再攻略一次”清理本周目数值，但保留已经达成的结局。
- `IsPreviewMode` 在正常游玩、结局回顾、开发者预览、返回标题和重新开始等路径中不会意外泄漏。
