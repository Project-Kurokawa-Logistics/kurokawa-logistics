# 《圣诞大攻略：雷琥》重构方案

- 状态：提案，等待确认后实施
- 编写日期：2026-10-27
- 目标分支：`main`
- 目标目录：`Ink Projects/圣诞大攻略：雷琥/`
- 当前范围：只制定方案；本文件不代表已经修改或测试任何 Ink 源码

## 1. 重构目标

本次重构不是重写故事，而是把现有设计表达得更明确、可维护、可测试：

1. 保留原作叙事意图，包括故意重复的选项、没有额外数值后果的角色扮演选项、现有剧情文本和开发者菜单。
2. 把“角色选择记录”“正片结局达成记录”“开发者预览状态”拆分为不同概念。
3. 让结局回顾只列出玩家通过正片实际走到的结局，而不是仅仅访问过对应 Knot 的结局。
4. 避免开发者菜单直接预览结局后，污染正式结局统计或意外满足多周目解锁条件。
5. 保留现有多周目体验，并明确新周目重置哪些数据、不重置哪些数据。
6. 每项逻辑修改都配套回归测试；不以“能编译”替代“行为正确”。

## 2. 已确认的设计决定

以下内容来自作者对初次逻辑审查的澄清，重构时应视为需求，而不是待修复 Bug。

| 项目 | 已确认的意图 | 重构处理 |
|---|---|---|
| A-01 宿舍线角色倾向 | 不按最高计数竞争；选择过对应角色即可作为路线资格 | 将条件写成明确的“计数大于 0”，不再把逻辑 `or` 当作数值比较。若多个角色都被选择过，建议保留当前分支顺序作为优先级：夜痕 → 岑烨 → 雷琥；实施前把这个优先级写入测试 |
| A-02 F8 结局计数 | 需要修复 | F8 是公共剧情/分流节点；只有玩家选定“担心身体”并走完该结局，才记录 F8 达成 |
| A-03 F5 重复选项 | 故意设计，用来表现主角已经沦陷 | 保留，不合并、不改写 |
| A-04 快餐店与午餐相关设定 | 快餐店由雷琥哥哥经营，属于既定设定 | 不作为剧情 Bug 修复；保留相关文本 |
| A-05 F8 分类 | 以结局回顾菜单中的“一般结局《担心身体》”为准 | 将正文标题中的“好结局”同步为“一般结局”，保持菜单、正文和文档一致 |
| A-06 F6 选项汇合 | 故意用相同后果表现主角状态，不是 Bug | 保留三个选择及其汇合结构 |
| A-07 结局回顾规则 | 只有正片实际达成的结局才应出现在回顾中 | 使用独立的结局达成状态；不能只依赖 Knot 访问记录 |

## 3. 建议的状态模型

### 3.1 三类状态必须分开

**A. 当前周目的数值状态**

继续使用现有变量：

- `Rate_LeiHu`
- `Choose_YeHen`
- `Choose_CenYe`
- `Choose_LeiHu`

这些变量用于当前路线判断和调试显示。开始新周目时由 `CleanData` 重置。

**B. 正片结局达成状态**

建议在 `Z_VAR.ink` 中新增一组布尔变量，例如：

- `Ending_F1_Achieved` 到 `Ending_F11_Achieved`，初值均为 `false`。

它们表示“是否至少通过正片完整达成过这个结局”，而不是“是否进入过这个 Knot”。每个结局只记一次，重复达成不增加结局总数。

这些标记**不应写进 `CleanData` 的重置列表**，这样普通的“再攻略一次”不会抹去已达成结局。按当前作品提示，玩家主动使用 RESTART 会重置 Ink 整个故事状态；是否需要跨 RESTART 持久化，属于另一项存档设计，不在本次最小重构范围内。

**C. 开发者预览状态**

建议新增一个短生命周期的布尔状态，例如 `IsDevPreview`，只在开发者菜单直接查看结局时设为 `true`。

- 从 `All_Finale` 进入任意结局前开启预览状态。
- 在结局完成/统一结束流程中清除预览状态。
- `CleanData` 也将该状态设为 `false`，避免异常退出后影响新周目。
- 预览状态不能被当成正式解锁或达成标记。

## 4. 结局记录与菜单的具体改法

### 4.1 只在结局真正结束时记账

F1–F7、F9–F11 应在各自结局正文末尾、跳转到 `TheEnd` 之前记录达成状态，并且仅当 `IsDevPreview == false` 时记录。

F8 需要特殊处理：`Finale.F8` 先展示公共剧情，再提供 F9、F10 和“担心身体”三个去向。因此：

- 进入 F8 本身不代表达成 F8。
- 选择“担心身体”并走完这条结局，才设置 `Ending_F8_Achieved = true`。
- 从 F8 继续进入 F9 或 F10，只记录实际到达的 F9 或 F10，不记录 F8。
- 从开发者菜单预览 F8/F9/F10 时，所有达成标记都不变。

这样可以解决 F8 既是分流节点又被计作结局的问题。

### 4.2 `CountFinale` 只统计达成标记

当前 `CountFinale` 根据 `Finale.F1` 等 Knot 是否被访问来增加计数。建议改成统计 `Ending_F1_Achieved` 至 `Ending_F11_Achieved`：

- 访问某个 Knot 不再自动等于达成结局。
- `FinaleCount` 表示正片已达成的不同结局数量。
- `TheEnd` 和“更多信息”中的结局回顾入口可以继续调用 `CountFinale`，但计算来源必须是达成状态。

### 4.3 `FinaleList` 只看达成标记

将当前类似 `{Finale.F1}` 的显示条件替换为对应的 `Ending_F1_Achieved` 条件。这样：

- 通过正片达成过的结局会显示在回顾中。
- 仅通过开发者菜单看过的结局不会显示在正式回顾中。
- 多周目达成的结局会持续保留，直到玩家使用会重置整个 Ink 状态的 RESTART。

### 4.4 开发者菜单继续保留，但与正式回顾分离

保留现有多次点击解锁开发者菜单的机制，以及 `All_Finale` 中直接进入各结局的预览入口。

开发者菜单的作用是**方便作者查看内容**，而不是伪造正式游玩记录。因此每条预览入口都应在跳转前设置 `IsDevPreview = true`。正式结局回顾不依赖 `All_Finale` 的访问记录。

同时建议将 F9/F10 的多周目条件从 Knot 访问状态改为正片达成状态：

- F9：`Ending_F2_Achieved` 为真时可见。
- F10：`Ending_F2_Achieved` 与 `Ending_F7_Achieved` 均为真时可见。

这样，开发者直接预览 F2 或 F7 不会意外解锁正片隐藏路线。若作者希望开发菜单也能强制解锁隐藏路线，应另设显式开发开关，而不是依赖副作用。

## 5. 宿舍线分支条件

在 `G_Dormitory.ink` 中，把当前含有 `Choose_X > (Choose_Y or Choose_Z)` 的条件改为明确的“是否选择过”判断，而不是最高分比较。

建议的规则：

1. `Rate_LeiHu < 3` 时进入角色倾向分流。
2. `Choose_YeHen > 0` 时优先进入 F5。
3. 否则，`Choose_CenYe > 0` 时进入 F6。
4. 否则，`Choose_LeiHu > 0` 时进入 F7。
5. 如果三者均为 0，则沿用现有默认路线 F7。
6. `Rate_LeiHu >= 3` 时进入 F8。

这里的夜痕 → 岑烨 → 雷琥是建议采用的冲突优先级，原因是它最接近现有代码的分支顺序、改动也最小。若多个角色都曾被选择过，必须通过测试确认优先级，不应再用隐式逻辑表达式决定路线。

保留现有计数变量与 `ShowData` 调试输出；本次只调整路线条件，不删除计数功能。

## 6. 结局名称与既定设计

- F8 正文分类标题与回顾菜单统一为“一般结局《担心身体》”。
- 保留 F5 中三个重复的“服从”选项。
- 保留 F6 中多个选项汇入同一后果的设计。
- 不因 A-04 修改快餐店或午餐相关剧情；快餐店由雷琥哥哥经营是已确认设定。
- 不重写结局正文，不统一角色说话风格，不做与本次目标无关的文本润色。

## 7. 实施阶段

### 阶段 0：建立基线

- 记录当前分支和提交。
- 先确认项目实际使用的 Ink 编译器/宿主环境。
- 运行现有版本并记录主线入口、F1–F11、结局回顾和开发者菜单的基线行为。

### 阶段 1：明确状态模型

- 在 `Z_VAR.ink` 增加结局达成标记与开发者预览标记。
- 明确 `CleanData` 只清理当前周目数值，不清除结局达成记录。
- 在 `TheEnd` 的统一结束流程中确保预览模式被清除。

### 阶段 2：接入结局达成记录

- 在 F1–F7、F9–F11 的结局末尾添加受预览状态保护的达成记录。
- 在 F8 仅为“担心身体”独立结局添加达成记录。
- 把 `CountFinale` 改为统计达成标记。
- 把 `FinaleList` 改为显示达成标记。

### 阶段 3：隔离开发者预览与多周目解锁

- 保留多次点击开发者菜单的原机制。
- 从 `All_Finale` 预览结局前开启预览状态。
- 将 F9/F10 的正常解锁条件改为正式达成记录，避免开发者预览污染正片进度。
- 验证预览结束后能正常开始新周目，且预览本身不增加结局数量。

### 阶段 4：明确路线条件与标签

- 将宿舍线条件改为明确的 `Choose_X > 0`。
- 按确定的冲突优先级测试多角色均被选择的情况。
- 将 F8 正文分类标签改为“一般结局”。

### 阶段 5：完整回归与文档同步

- 执行下方测试矩阵。

## 8. 必须通过的回归测试

### 正片结局记录

- [ ] 通过正常剧情分别达成 F1–F11，逐一确认相应结局在回顾中出现。
- [ ] 只进入 F8 并继续走向 F9 时，回顾只新增 F9，不新增 F8。
- [ ] 只进入 F8 并继续走向 F10 时，回顾只新增 F10，不新增 F8。
- [ ] 选择“担心身体”并走完后，回顾新增 F8，分类显示为“一般结局”。
- [ ] 同一结局重复达成，`FinaleCount` 仍只增加一个唯一结局。
- [ ] 尚未在正片达成的结局不出现在 `FinaleList` 中。

### 开发者菜单隔离

- [ ] 按原有方式连续点击，确认开发者菜单仍能解锁。
- [ ] 从 `All_Finale` 预览每个结局，确认 `FinaleCount` 不增加，正式回顾不新增条目。
- [ ] 开发者预览 F2/F7 后开始新周目，确认 F9/F10 不会仅因预览而解锁。
- [ ] 预览结束后返回标题，再正常开始新周目，确认预览状态已清除，正片结局仍能正常记录。

### 多周目与重置

- [ ] 正片达成 F2 后，使用普通“再攻略一次”进入新周目，确认 F9 按设计解锁。
- [ ] 正片分别达成 F2 与 F7 后，确认 F10 按设计解锁。
- [ ] 新周目开始时，好感度和人物选择计数重置。
- [ ] 新周目开始时，已达成结局标记保留。
- [ ] 使用 RESTART 后，确认行为与作品现有“重置数据”提示一致。

### 宿舍线条件

- [ ] 只选择夜痕：进入 F5。
- [ ] 只选择岑烨：进入 F6。
- [ ] 只选择雷琥：进入 F7。
- [ ] 多个角色均被选择：按已记录的优先级进入预期路线。
- [ ] 三个计数全为 0：进入默认 F7。
- [ ] 好感度为 2 时走低好感分支；为 3 时进入 F8。

## 9. 本次不做的事情

- 不改写或删减剧情正文。
- 不把故意的重复选项或汇合选项“修正”为不同后果。
- 不改变角色选择的设计含义，不改成最高计数竞赛。
- 不删除开发者菜单。
- 不在未测试前声称编译或运行成功。
- 不顺手重命名大量 Knot、文件或变量；如后续确有必要，应单独提出迁移计划。

## 10. 验收标准

重构完成后应同时满足：

1. 正片达成记录、开发者预览与当前周目计数互不混淆。
2. 正式结局回顾仅显示正片实际达成的结局。
3. F8 作为分流节点时不会被误记为独立结局。
4. 开发者菜单仍可用于直接预览全部结局，但预览不会改变正式结局记录或多周目解锁状态。
5. 角色选择条件符合“选择过即可”的设计，并对多角色冲突优先级有明确、可重复的行为。
6. 故意的叙事设计和已确认设定保持不变。
7. 编译与回归测试结果有记录，文档与实际代码同步。
