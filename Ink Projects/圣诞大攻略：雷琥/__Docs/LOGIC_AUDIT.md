## A-01：宿舍线的角色选择判定

- 严重程度：高（曾导致正常结局可达性阻塞，现已解决）
- 状态：已按 RAW 规则实现并通过两套自动回归（19/19）
- 位置：[`G_Dormitory.ink`](../G_Dormitory.ink) 的开场选择与 [`RouteDecision`](../G_Dormitory.ink)；[`Z_VAR.ink`](../Z_VAR.ink) 的 `Dormitory_LeiHu_Direct` 声明与 `CleanData`
- 设计意图（RAW 原稿）：
  - 开场“夜痕的事”：好感不变，偏向夜痕。
  - 开场“岑烨的事”：好感不变，偏向岑烨。
  - 开场“雷琥的事”：好感增加，直接导向雷琥线结局。
  - 低好感时按“大体偏向”分流，F5／F6／F7 分别是夜痕／岑烨／雷琥主导的结局；高好感进入 F8。
- 实现：
  1. 开场“夜痕的事”保持 `Choose_YeHen++`。
  2. 开场“岑烨的事”改为 `Choose_CenYe++`，删除此处原有的 `Rate_LeiHu++`。
  3. 开场“雷琥的事”保留 `Rate_LeiHu++`，新增 `Choose_LeiHu++`，并设置当前周目状态 `Dormitory_LeiHu_Direct = true`。
  4. `RouteDecision`：`Rate_LeiHu < 3` 时先看 `Dormitory_LeiHu_Direct`（真 → F7），再用 `A > B && A > C` 形式判断唯一最高计数（Y→F5、C→F6、L→F7），最后的无条件 `-> Finale.F7` 承接平局与全零。`Rate_LeiHu >= 3` 仍直接进 F8。锚点保留。
  5. 追问的两个三级分支“是啥样的活，工资高吗？”与“会不会累？”都按 RAW 352-359 各加 1 点好感；后者原先漏写，2026-10-29 补齐。
  6. `Dormitory_LeiHu_Direct` 在 `CleanData` 重置为 `false`，不跨普通周目保留，也不是正式结局记录。
- 自动验证：
  - 注入矩阵 32 组（好感 2/3 × 三个计数 8 种组合 × Direct 真/假）全部符合规则。
  - 45 条正常宿舍路径分布为 F5 = 6、F6 = 6、F7 = 12、F8 = 21。
  - 正常 `F2 → F7 → F10` 多周目链路不注入变量即可通过。
  - 两个三级分支都有逐步好感断言（1 → 2 → 3）。
- 历史：2026-10-28 曾采用“选择过即具备资格”（`Choose_X > 0`）+ 夜痕 → 岑烨 → 雷琥固定优先级；该方案使正常 F7 不可达、正片 F10 无法验证，两套回归停在 18/19。2026-10-29 作者确认改按 RAW 原稿执行，旧方案作废。
