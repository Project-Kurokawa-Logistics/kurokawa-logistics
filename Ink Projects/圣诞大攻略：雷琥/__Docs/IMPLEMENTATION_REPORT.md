## A-01 可达性核对

正常选择“开始攻略 → 旁敲侧击 → 说明白 → 同意 → 夜痕的事 → 和岑烨打招呼 → 正事要紧，还是老实在宿舍里督促雷琥”，真实 InkJS 运行结果为 `Choose_YeHen=1 / Choose_CenYe=1 / Choose_LeiHu=1 / Rate_LeiHu=2`，基线进入 F7。未注入变量。三组选择顺序执行，因此同一周目可以选择多名角色。

“夜痕的事 → 和岑烨打招呼 → 看棒球特训”得到 `Y1/C2/L0，Rate0`，基线进入 F6；若采用 `> 0` 与夜痕优先，会进入 F5。因此必须确认冲突规则，不能将其当作无行为变化的语法改写。

从正常标题进入宿舍后，枚举 5 种第一组对话过程 × 3 种招呼 × 3 种活动，共 45 条选择路径。未注入变量：基线到达 F5 8 条、F6 4 条、F7 15 条、F8 18 条。27 条低好感路径若采用原建议“夜痕 → 岑烨 → 雷琥”的 `> 0`，将变为 F5 21 条、F6 6 条、F7 0 条。这会让 F7 及依赖其正式记录的 F10 无法正常达成。原建议不能直接落地，已经把运行证据交给作者决定。

完整宿舍周目必在第二、三组分别增加一次选择计数，三计数全零在正常完整流程中不可达。低好感且只有雷琥计数非零也不可达：避开夜痕首选会先增加至少 1 好感，第三组选雷琥再加 2，进入 F8。两者只能作为变量注入边界测试。
